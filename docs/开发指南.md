# GravityD 开发指南

面向要在本仓库上做二次开发的同学。读完应能独立：拉起本地环境、加一张业务表、挂侧栏菜单、写列表 CRUD、在浏览器走通验收。

Agent 加模块时走 [`.cursor/skills/base-server-app`](../.cursor/skills/base-server-app/SKILL.md)。根目录 `SKILL.md` 是历史 FastAPI 全栈说明，**不是当前运行时路径**。

二次开发 CLI 使用说明：[gravityd-cli.md](./gravityd-cli.md)（对标 `npx @insforge/cli link --project-id <id>`）。自托管没有云端项目，`link` 只绑定当前仓库：

```bash
npx --yes ./packages/gravityd-cli link --project-id local -y
npx --yes ./packages/gravityd-cli module add --domain crm --resource customer --title 客户 --dry-run
```

---

## 1. 这是什么

GravityD 是团队内部的中后台脚手架。新项目从这里拉起登录、RBAC、菜单和 CRUD，而不是从零搭。

| 层 | 实际技术 | 不要当成 |
|---|---|---|
| 管理端 | `frontend/web`：Vue3 + Vite + TypeScript + Element Plus，hash 路由，`BASE_URL=/web` | 不要再打 FastAPI `/api/v1` |
| 运行时后端 | 仓库内**自托管 InsForge**（Auth + Postgres + RLS），Compose 项目名 `gravityd-insforge` | 不要启动 8001，不要打 FastAPI `/api/v1` |
| 业务库 | InsForge Postgres：`public.*` + `auth.users` | 不要用 `docker/` 里旧的 MySQL 栈当默认 |

二次开发默认只改两处：

- `insforge-app/migrations/`：表、RLS、菜单种子
- `frontend/web/`：API、页面；业务路由由菜单驱动，不要手写 `addRoute`

## 2. 本地环境

依赖：Docker Desktop（引擎 Running）、Node.js ≥ 20。

本机若已有别人的 Postgres `5432` / Redis `6379`，**不要停、不要改端口抢占**。InsForge Postgres 必须映射 `5433`，PostgREST `5440`。

### 首次初始化

```bash
bash scripts/init.sh                         # 交互选择 InsForge 或 Firebase
bash scripts/init.sh --provider=insforge     # 克隆 insforge/、避让端口、启栈、迁移、超管、写前端 env
bash scripts/init.sh --provider=firebase     # 只写 Firebase 环境模板，不拉本地 Docker
bash scripts/init.sh --provider=firebase --dry-run
bash scripts/dev.sh                          # InsForge 模式：确保栈起来后启动 Vite
```

选 Firebase 后，把 `frontend/web/.env.development` 里的 `VITE_FIREBASE_*` 换成真实项目凭据，再播种：

```bash
cd frontend/web && npm run seed:firebase
# 或: node scripts/seed-firebase.mjs
```

等价 CLI：`gravityd init --provider=insforge|firebase`，`gravityd link --project-id local --provider=firebase -y`。

`insforge/` 由 init 克隆，已在 `.gitignore`，不要提交。**禁止**在仓库根执行官方 InsForge `setup.sh`（会破坏本仓 git）。**禁止**把 InsForge 嵌进 `docker/docker-compose.yaml`。

### 日常启动

```bash
bash scripts/insforge-up.sh          # 只拉已有 compose
bash scripts/dev.sh                  # 推荐：启栈 + 写 env + Vite
```

本机 `~/Library/pnpm` 可能无写权限，不要用仓库根 `pnpm add`，也不要依赖 `pnpm run dev`。前端在 `frontend/web` 内：

```bash
cd frontend/web
# 没有 node_modules 时再在本目录安装
./node_modules/.bin/vite --mode development
```

依赖（含 `@insforge/sdk`）只装在 `frontend/web`。

### 入口与账号

| 入口 | 地址 | 账号 |
|------|------|------|
| 管理后台 | http://127.0.0.1:5180/web | `admin@local.dev` / `123456` |
| InsForge 控制台 | http://127.0.0.1:7130 | `admin` / `insforge/.env` 的 `ROOT_ADMIN_PASSWORD` |
| InsForge Postgres | `127.0.0.1:5433` | 容器内 `postgres` / 库 `insforge` |
| PostgREST | `127.0.0.1:5440` | 一般不直接打 |

控制台与后台不是同一套登录。种子超管 `profiles.id`：`cc49c595-0764-4ff8-b4e5-f13f5e696905`（username `admin`）。登录框填 `admin` 时会拼成 `admin@local.dev`（`toLoginEmail`）。

旧名称 / 过期 JWT 先 `localStorage.clear()` 再登录。JWT 大约 15 分钟；跨域不要依赖 cookie。前端 SDK：`isServerMode: true`。

iframe 打开控制台若空白，用页内「新窗口打开」。

## 4. 数据流

```
浏览器 (5180/web)
    │  hash 路由  /#/system/user
    ▼
Vue 页面  →  api/module_*/**.ts
    │  insforge.database / insforge.auth
    ▼
InsForge 网关 (7130)
    ├─ Auth          → auth.users
    └─ /api/database/records/<table>  → Postgres + RLS
```

不要手写 `/rest/v1`。SDK 访问路径是网关 `/api/database/records/<table>`。

用户主键对齐 `auth.users(id)`（UUID）。业务表关联用户用 `profiles.id`，**不要自建密码字段**。密码只存在 Auth。

### 应用一条新迁移

下一个序号从 **009** 起。不要改已经落地的 001–008 语义（尤其 002）。

```bash
npx --yes ./packages/gravityd-cli migrate apply --file 009_your_module.sql

# 或单独套一条
cd insforge
docker compose exec -T postgres psql -U postgres -d insforge -v ON_ERROR_STOP=1 \
  < ../insforge-app/migrations/009_your_module.sql
```

或把文件名追加进 `insforge-app/scripts/apply-extra.sh`（不要写进会跑 002 的 `apply.sh`）。

每条新迁移末尾加：

```sql
NOTIFY pgrst, 'reload schema';
```

菜单增量的 `DELETE` **必须带 id 范围**，避免误删其它模块。

### 系统表（已占用）

`profiles`、`sys_dept`、`sys_role`、`sys_menu`、`sys_user_roles`、`sys_role_menus`、`sys_dict_*`、`sys_param`、`sys_position`、`sys_user_positions`、`sys_notice`、`sys_login_log`、`sys_operation_log`、`sys_ticket`、`sys_ticket_comment`、`sys_version`、`sys_online`。

### RLS 默认

业务表：`ENABLE ROW LEVEL SECURITY` + `authenticated` 全表 `FOR ALL USING (true) WITH CHECK (true)`。需要匿名读的配置/公告再加 `anon` SELECT。先保证能开发，按角色收紧以后再改 policy。

字段惯例：`status` `0` 正常；列名 `"order"` 越小越前；审计 `created_time` / `updated_time`。关联用户一律 UUID → `profiles(id)`。

## 7. 菜单、权限与路由

业务页**不手写路由表**。登录后菜单进入 `MenuProcessor` → `RouteRegistry` 动态注册。

### 菜单类型

| `type` | 含义 | 关键字段 |
|--------|------|----------|
| `1` | 目录 | `route_path` 绝对，如 `/crm`；`redirect` 绝对，如 `/crm/customer` |
| `2` | 页面 | `route_path` 相对，如 `customer`；`component_path` 如 `module_crm/customer/index`（无 `.vue`，对应 `src/views/...`） |
| `3` | 按钮 | 只有 `permission`，path / component 空 |

其它：`route_name` 全局唯一（并与页面 `defineOptions({ name })` 一致，KeepAlive 才生效）；`scope` 后台用 `web`；`hidden=true` 侧栏不显示。

改菜单后重新登录，或走现有 `refreshPermissions`，动态路由才会更新。

### 菜单 id 分段

| 区间 | 用途 |
|------|------|
| `1–49` | 一期系统 |
| `50–89` | 扩展系统 |
| `90–99` | InsForge（概览 / 控制台） |
| **`100` 起** | **新业务**，按 10 或 50 一段预留，写进迁移注释 |

### 权限码

格式：`module_<域>:<资源>:<动作>`。

动作用：`query` / `create` / `update` / `delete` / `patch` / `detail` / `export`。

按钮用 `v-hasPerm="'module_crm:customer:create'"`（支持数组）；代码里用 `useAuth().hasAuth(...)`。

### 动态路由注意

- `MenuProcessor` 把相对 `route_path` 拼成绝对路径。
- 目录 `redirect` 优先用库里的绝对路径。
- `/home`、`/dashboard/*` 是静态演示壳，不要当业务后端。
- `RouteRegistry` 不会注册第一段为 `home|profile|changelog|dashboard` 的后端菜单。
- 地址是 hash：`http://127.0.0.1:5180/web/#/crm/customer`。

侧栏：点目录标题（图标/文字）进入第一个叶子；箭头只展开。工作标签会丢掉 404 / 403 / 500 旧路由。

## 8. 前端约定

### API

路径：`frontend/web/src/api/module_<域>/<资源>.ts`。

对照实现：[`frontend/web/src/api/module_system/position.ts`](../frontend/web/src/api/module_system/position.ts)。

硬规则：

1. 客户端只用 [`frontend/web/src/utils/insforge.ts`](../frontend/web/src/utils/insforge.ts) 的 `insforge`（`createClient({ baseUrl, anonKey, isServerMode: true })`）。
2. 包装必须走 `ok()` / `unwrap()` / `pageOf()` / `rangeOf()` / `buildTree()`。`ok()` 的 `code` 必须是 `ResultEnum.SUCCESS = 0`。
3. 列表：`select('*')` 后**内存过滤 / 排序 / 分页**。禁止 `{ count: 'exact' } + range`（`head: true` 的行数统计除外）。
4. 列名 `"order"` **禁止** `.order('order')`，在内存里 `sort`。
5. 未登录用 `HttpError(401)`（见 `currentUserId()`），不要吞掉后让页面空白。
6. 导出 / 导入 / 上传未做就 `throw new Error("未迁移导出")`，不要假装打 FastAPI。
7. 树形用 `buildTree`。下拉选项只 `select` 必要列。

```ts
import { insforge } from "@/utils/insforge";
import { ok, pageOf, rangeOf, unwrap } from "@/utils/insforge-api";

const { pageNo, pageSize } = rangeOf(query?.page_no, query?.page_size);
let builder = insforge.database.from("crm_customer").select("*");
if (query?.name) builder = builder.ilike("name", `%${query.name}%`);
const rows = ((unwrap(await builder) as CustomerTable[]) || []).slice();
rows.sort((a, b) => (a.order ?? 0) - (b.order ?? 0));
return ok(pageOf(rows.slice((pageNo - 1) * pageSize, pageNo * pageSize), rows.length, pageNo, pageSize));
```

### 页面

对照：[`frontend/web/src/views/module_system/position/index.vue`](../frontend/web/src/views/module_system/position/index.vue)。

复制岗位页，改 API、权限码、列、表单、`useTable({ apiFn })`。

- 列表：`FaSearchBar` + `FaTable` + `useTable`
- 弹窗：`useCrudDialog` / `useCrudForm` + `FaDialog`
- 列：`useTableColumns`
- 不要手写 `ElTable` / axios / `/api/v1`
- 页面私有组件放同目录 `components/`；公共组件先搜 `FaXxx`
- `defineOptions({ name })` 必须等于菜单 `route_name`
- 文案用 `$t('key')`，同时改 `locales/langs/zh.json` 与 `en.json`
- 图标：`FaSvgIcon` + iconify（`ri:` / `ep:`）
- 有 WebSocket / 定时器的页必须在 `onDeactivated` 释放，`onActivated` 恢复；`onUnmounted` 在 KeepAlive 下不会每次都走

### 不要迁进侧栏 / 不要接 InsForge

页面文件可以留着，但不要接 SDK、不要进菜单：

代码生成、工作流、定时任务、AI、内部聊天、服务器监控、缓存监控。

## 9. 加一个业务模块（标准顺序）

以 CRM 客户为例：域 `crm`，资源 `customer`，菜单 id `100–109`。SQL 文件用 `007_crm_customer.sql`（006 已被品牌占用）。完整模板见 [new-module.md](../.cursor/skills/base-server-app/new-module.md)。

推荐用 CLI 生成再改字段：

```bash
npx --yes ./packages/gravityd-cli module add --domain crm --resource customer --title 客户 --fields mobile:text
npx --yes ./packages/gravityd-cli migrate apply --file 007_crm_customer.sql
```

清单：

```
- [ ] SQL：表 + 索引 + RLS + 菜单 + SUPER_ADMIN 授权 + NOTIFY
- [ ] 应用迁移（docker compose exec psql，不要跑 002）
- [ ] API：insforge.database + ok/unwrap，对照 position.ts
- [ ] 页面：复制 module_system/position，改 API / 权限码 / 列
- [ ] 菜单 route_path / component_path / permission / route_name 对齐
- [ ] 浏览器：清 token → 登录 → 点侧栏 → 列表 / 新增 / 编辑 / 删除
```

菜单种子要点：

```sql
DELETE FROM public.sys_role_menus WHERE menu_id >= 100 AND menu_id < 110;
DELETE FROM public.sys_menu WHERE id >= 100 AND id < 110;
-- 100 目录 / 101 页面 / 102+ 按钮
-- INSERT … SUPER_ADMIN 授权
SELECT setval(pg_get_serial_sequence('public.sys_menu', 'id'), (SELECT MAX(id) FROM public.sys_menu));
NOTIFY pgrst, 'reload schema';
```

大域新业务可按团队 6A 规范写 `docs/<任务名>/`。普通 CRUD 按上面清单即可。

## 12. 常见问题

| 现象 | 处理 |
|------|------|
| 登录后空白 / 500 | JWT 过期或旧 token。`localStorage.clear()` 再登录 |
| `[路由警告] 找不到组件` | `component_path` 与 `src/views/...` 不一致，或没重新登录拉菜单 |
| 侧栏没有新模块 | 菜单没授权给当前角色；或 id 冲突被 DELETE 掉；重新登录 |
| 列表报错 / 空失败 | 查是否用了 `{ count: 'exact' } + range`，或 `.order('order')` |
| 控制台 iframe 空白 | 用「新窗口打开」；控制台账号不是后台那套 |
| `5432` 被占用 / 连错库 | 确认 `insforge/.env` 的 `POSTGRES_PORT=5433`，不要动别人的容器 |
| 仓库根 `pnpm` 失败 | 只在 `frontend/web` 装依赖，用本地 `./node_modules/.bin/vite` |
| 页面缓存不生效 | `defineOptions({ name })` ≠ 菜单 `route_name` |
| 导出按钮一点就打 FastAPI | 应 `throw new Error("未迁移导出")` |
| 误跑 002 | 业务表被 TRUNCATE。只能重新 `init`（空库）或从备份恢复，不要当日常脚本 |

改了 UI / 路由 / 列表，必须在浏览器点侧栏走通，不要只截一张图。相关页若共享同一份 store / 菜单，也要点一遍。
